# UAV---Navigation-in-BAR-
This repository contains a 2D Python simulation of a Unmanned Aerial Vehicle (UAV) navigating a complex obstacle environment. The project implements a greedy local-search path-planning algorithm coupled with a Dynamic Approximate Path (DAP) escape mechanism to solve the "Blind Alley Region" (BAR) problem (i.e., local minimum traps).📂 Repository Structurecodenav.py: The core simulation engine. This script handles the drone's physics, sensor raycasting, point ranking ($\alpha$ and $\beta$ penalties), and the execution of both Algorithm 2 (Exploration) and Algorithm 1 (DAP Retreat).Code_of_map.py: The environment generation script. It constructs the physical 2D polygon boundaries (like the Gauntlet Canyon map).our map.png: The finalized visual output of the pathfinding simulation, demonstrating the drone's trajectory, the DAP rubber-band escape lines, and the geometric optimization funnels.historical_coords.csv: A step-by-step output log tracking the exact $(X, Y)$ coordinate trajectory of the UAV throughout the simulation.open_points_rankings.csv: A diagnostic log detailing the mathematical cost calculations for every selected target node, useful for debugging the balance between distance and angular deviation.🧠 Core Algorithmic ConceptsThis simulation is built upon two distinct operational modes that interact via strict Set Theory to prevent infinite loops and micro-vibrations.1. Algorithm 2: The Greedy Explorer (Local Search)Under normal conditions, the UAV operates using a limited sensor radius ($r=15$). It scans the environment, splits open areas $> 180^\circ$ to find boundary edges, and ranks available points based on:$\alpha$ (Distance Penalty): Pulls the drone toward the global goal.$\beta$ (Angular Penalty): Provides "branch inertia," penalizing sharp turns to keep the drone hugging walls smoothly instead of ping-ponging.2. The Inactive Point Protocol (Preventing Paradoxes)To prevent the UAV from simply turning around and walking backward in open space, the algorithm maintains a strict Visited Set ($S_t^e$). Any new point generated by the local camera that falls within the established Visited Set is immediately classified as Inactive and destroyed. The UAV is forced to constantly push into unknown territory.3. Algorithm 1: The DAP Escape (Solving the BAR Trap)Because Algorithm 2 is purely greedy, it will inevitably fly into U-shaped traps (Local Minimums/Blind Alley Regions) and run out of viable forward options.When a BAR is triggered:Memory Retrieval: The UAV ignores its local camera and queries its Active Pool ($O_t^e$)—a global memory graph of all valid doors and branches it bypassed earlier.The Rubber Band: It selects the best historical point and extracts the jagged memory path (sequence_F) leading back to it.Optimization: Algorithm 1 (DAP) pulls this jagged sequence taut like a rubber band, snapping a straight flight path around the physical corners of the obstacles.Geometric Bundles: The area trapped between the raw memory path and the straight DAP shortcut forms a Convex Hull Bundle (visualized in green), representing the exact regional space the algorithm successfully optimized away.🚀 Setup and ExecutionDependencies:matplotlib (for simulation rendering)shapely (for geometric line-of-sight and polygon calculations)numpy (for raycast angle arrays)To Run:Execute codenav.py. The simulation will automatically compile the map, deploy the UAV, and generate the CSV logs in the /logs directory upon completion.
